# Decentralized & Tamper-Proof FIR Management System (Web3 Police Portal)

Hybrid architecture: readable FIR data lives in **PostgreSQL** (off-chain); only the **SHA-256 hash**, timestamp and officer wallet go to an **Ethereum smart contract** (on-chain). Anyone can verify a FIR by FIR ID or by scanning the QR on the receipt.

```
contracts/   Hardhat + Solidity (FIRRegistry, roles, append-only versions, tests, deploy script)
web/         Next.js app: complaint form, wallet connect, receipt + QR, public Verify page, API, auditor
.env         ONE file with all keys (created from .env.example)
```

## Quick start (Sepolia testnet)

Requirements: Node.js 20 or 22, a PostgreSQL database, MetaMask.

```bash
npm run install:all     # installs contracts + web
npm run setup           # creates .env and generates EVIDENCE_ENCRYPTION_KEY
```

Open `.env` and replace the values marked in the table below, then:

```bash
npm run test:contracts  # optional: 5 contract tests
npm run deploy          # deploys to Sepolia, grants officer roles, writes the contract address into .env
npm run dev             # http://localhost:3000
```

## Keys to replace in `.env`

| Key | Where to get it |
|---|---|
| `RPC_URL` | Alchemy or Infura -> create app on **Sepolia** -> copy HTTPS URL |
| `DEPLOYER_PRIVATE_KEY` | MetaMask -> account menu -> Account details -> Show private key (use a **throwaway test wallet**, fund it from a Sepolia faucet) |
| `RELAYER_PRIVATE_KEY` | Another test wallet with Sepolia ETH. It pays gas when a citizen files without a wallet. May equal the deployer for a quick demo |
| `OFFICER_ADDRESSES` | Optional, comma separated wallet addresses of officers who sign with MetaMask |
| `DATABASE_URL` | Free Neon/Supabase Postgres URL, or `postgresql://user:pass@localhost:5432/dbname` (tables are created automatically) |
| `PINATA_JWT` | pinata.cloud -> API Keys -> New key -> copy JWT. Leave empty to skip IPFS (evidence is still hashed) |
| `EVIDENCE_ENCRYPTION_KEY` | Auto-generated by `npm run setup` (or `npm run genkey`). **Back it up: lost key = unreadable evidence** |
| `NEXT_PUBLIC_REGISTRY_ADDRESS` | Auto-filled by `npm run deploy` |

Never commit `.env` (already in `.gitignore`). Never use a wallet that holds real funds.

## Run fully locally (no faucet, no RPC key)

```bash
npm run chain           # terminal 1: local blockchain (leave running)
```
In `.env` set `RPC_URL=http://127.0.0.1:8545`, `NEXT_PUBLIC_CHAIN_ID=31337`, and for both private keys use the first two keys printed by `npm run chain` (public test keys). Then:
```bash
npm run deploy:local
npm run dev
```
MetaMask: add network RPC `http://127.0.0.1:8545`, chain ID `31337`, and import one of the printed test accounts. Restarting the chain resets it, so redeploy after a restart.

## How it works

1. **Submit** -> backend validates, encrypts + pins evidence to IPFS, saves the row as `PENDING`, and builds the hash: SHA-256 of canonical JSON `{firId, record, evidence, salt}` (sorted keys, Unicode NFC, random 32-byte salt per FIR).
2. **Anchor**
   - *Wallet mode* (MetaMask connected): the officer signs `anchor(firId, hash)` and pays gas. The backend then **re-reads the transaction** and only marks the FIR `ANCHORED` if the on-chain event matches its own hash.
   - *Relayer mode* (no wallet): the backend wallet anchors on behalf of citizens.
3. **Receipt** shows FIR ID, hash, officer wallet, block timestamp, explorer link and a **QR** (`/verify?id=..&h=..`).
4. **Verify** (public, no wallet): `GET /api/verify/:id` re-hashes the DB record and compares with the contract. Results: `AUTHENTIC`, `TAMPERED`, `DELETED` (on-chain but missing in DB), `NOT_ANCHORED` (in DB, never anchored), `PENDING`, `FORGED_QR`, `UNKNOWN`. No personal data is returned.
5. **Auditor**: `npm run audit` re-verifies every FIR and exits with code 1 on any mismatch. Schedule it with cron or GitHub Actions.

Demo helpers: with `NEXT_PUBLIC_DEMO_MODE=true` the Verify page shows buttons to simulate DB tampering and restore. Set it to `false` for anything public.

## Tested

- Contract: 5 Hardhat tests (roles, versions, empty hash, no delete).
- Full backend flow on a local chain + PostgreSQL: relayer submit, wallet-mode confirm, authentic, tampered, forged QR, deleted, not anchored, unknown, pending, auditor, and that a transaction for a different hash is rejected.

## Not included / limits

- **Not browser-tested:** the MetaMask popup flow and the UI were not clicked through; only the backend/API flow above was. Expect small UI fixes.
- **OCR for legacy handwritten FIRs** is not built (needs a Vision/Document Intelligence key and a human-review step before anchoring).
- Plain CSS is used (same look as the Mumbai Police style), not Tailwind.
- No officer login: anyone can use relayer mode. Add authentication and rate limits before any real use.
- Evidence decryption tool is not included. Stored layout on IPFS: `[12-byte IV][16-byte tag][ciphertext]`, AES-256-GCM.
- A blockchain proves a record has **not changed since anchoring**, not that the complaint was true. Sepolia is a public testnet, so use real data only on a permissioned chain in India (DPDP Act 2023). FIR registration is governed by Section 173 BNSS.
